# Architecture Overview

This project uses a **prompt-driven orchestration** pattern where Claude Code reads markdown files as instructions and follows them conversationally. There's no runtime code—the entire system is defined through structured markdown files.

---

## Component Roles

### 1. Entry Points (Commands & Skills)

**Purpose:** Initialize the workflow and hand off to the orchestrator.

| Component | Location | Trigger | Role |
|-----------|----------|---------|------|
| **Command** | `.claude/commands/design-flow.md` | `/design-flow [idea]` | Explicit invocation with argument support |
| **Skill** | `.claude/skills/design-workflow/SKILL.md` | Natural language ("I want to build...") | Auto-discovery via description matching |

Both entry points:
1. Check for existing in-progress workflows (auto-resume detection)
2. Present resume options if workflows found
3. Capture the product idea (for new workflows)
4. Create initial state file with unique timestamp
5. Load the workflow orchestrator
6. Present welcome message

### 2. Workflow Orchestrator

**Purpose:** Central control flow defining phases, transitions, and checkpoints.

| Component | Location | Role |
|-----------|----------|------|
| **Workflow Guide** | `.claude/workflows/design-centered.md` | Defines phase sequence, iteration logic, state schema, checkpoint handling |

The orchestrator:
- Specifies which **role prompts** to read for each phase
- Defines **state schema** and when to save
- Contains **checkpoint templates** (user approval points)
- Handles **iteration logic** (retry, revise, proceed)

### 3. Role Prompts

**Purpose:** Phase-specific instructions that Claude follows when "taking on a role."

| Phase | Prompt File | Role Assumed |
|-------|-------------|--------------|
| Discovery | `discovery-phase.md` | Product & UX Researcher |
| Exploration | `exploration-explorer.md` | Design Explorer |
| Exploration | `exploration-critique.md` | Design Critic |
| Design | `design-phase.md` | Full-Stack Developer |
| Validation | `validation-phase.md` | Product & UX Researcher |

Each prompt contains:
- Role definition and responsibilities
- Output format templates
- Quality checklists
- Iteration behavior
- Examples and guidelines

### 4. State Persistence

**Purpose:** Enable workflow resumption across conversations.

| Component | Location | Role |
|-----------|----------|------|
| **State Files** | `.claude/state/workflow-{timestamp}.json` | Stores progress, artifacts, decisions |

State tracks:
- Current phase
- Phase-specific data (iterations, concepts, scores)
- Completed checkpoints
- User decisions

### 5. Output Artifacts

**Purpose:** Deliverables generated by the workflow.

| Artifact | Location | Generated By |
|----------|----------|--------------|
| Prototype | `output/{project-name}/` | Design phase |
| DESIGN_PROCESS.md | `output/{project-name}/` | Design phase |
| STAKEHOLDER_ALIGNMENT.md | `output/{project-name}/` | Validation phase |
| TEST_SCENARIOS.md | `output/{project-name}/` | Validation phase |

## Orchestration Flow

**How the workflow guide controls execution:**

```
1. Entry point loads workflow guide
2. Workflow guide says "Read .claude/prompts/discovery-phase.md"
3. Claude reads that prompt and follows its instructions
4. Claude generates artifacts per the prompt's format
5. Workflow guide defines checkpoint template
6. Claude presents checkpoint, awaits user decision
7. Based on decision, workflow guide specifies next action:
   - "approve" → proceed to next phase
   - "revise" → re-read prompt, iterate
8. Workflow guide says "Save state" → Claude writes JSON
9. Repeat for each phase
```

## Iteration Tracking Architecture

**Purpose:** Capture complete design evolution for traceability and auditability.

### How It Works

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                      ITERATION TRACKING FLOW                                 │
│                                                                              │
│  1. USER PROVIDES FEEDBACK                                                   │
│     User: "revise - personas need more specific pain points"                 │
│                                                                              │
│  2. WORKFLOW CAPTURES FEEDBACK                                               │
│     {                                                                        │
│       iteration: 2,                                                          │
│       timestamp: "2024-01-15T10:45:00Z",                                     │
│       user_action: "revise",                                                 │
│       user_feedback: "personas need more specific pain points",              │
│       changes_made: "Added domain-specific pain points with quotes"          │
│     }                                                                        │
│                                                                              │
│  3. APPEND TO ITERATION_HISTORY                                              │
│     phase_data.discovery.iteration_history.push({...})                       │
│                                                                              │
│  4. SAVE TO STATE FILE                                                       │
│     Write .claude/state/workflow-{timestamp}.json                            │
│                                                                              │
│  5. INCORPORATE INTO DESIGN_PROCESS.MD                                       │
│     Design agent reads state file, includes all iterations in documentation  │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### What Gets Tracked

| Phase | Tracked Data |
|-------|--------------|
| **Discovery** | PRD revisions, user feedback on personas/journeys/stakeholders |
| **Exploration** | Concept regenerations, rejected concepts, refinement requests |
| **Design** | Prototype revisions, file changes, UI/UX adjustments |
| **Validation** | Changes to alignment summaries and test scenarios |

### Benefits

1. **Auditability** - Complete record of what was tried and why
2. **Knowledge Capture** - Learn from rejected approaches
3. **Stakeholder Communication** - Show thorough exploration process
4. **Design Rationale** - Justify final decisions with evidence
5. **Team Handoff** - New team members understand design evolution

### DESIGN_PROCESS.md Generation

**Timing:** Generated AFTER user approves prototype at Checkpoint 3 (not during initial generation).

**Why:** Ensures documentation captures all prototype iterations, including any user-requested revisions.

**Process:**
1. User approves prototype (says "approve" or "approve with no validation")
2. Workflow reads complete state file from `.claude/state/workflow-*.json`
3. Extracts `iteration_history` arrays from all phases
4. Generates README.md (setup instructions) and DESIGN_PROCESS.md simultaneously
5. DESIGN_PROCESS.md includes:
   - Discovery iterations with feedback and changes
   - Exploration iterations showing concept evolution
   - Design iterations documenting prototype refinements
6. Complete design journey documentation created with full iteration history

## Multi-Workflow State Management

**Purpose:** Support multiple concurrent product ideas without interference.

### State File Isolation

Each workflow has an independent state file with unique timestamp:

```
.claude/state/
├── workflow-2026-01-17T10-30-00Z.json    # Habit tracker (in-progress)
├── workflow-2026-01-18T14-00-00Z.json    # Apartment tool (in-progress)
├── workflow-2026-01-19T09-15-00Z.json    # Meal planner (completed)
└── archive/
    └── workflow-2026-01-05T08-00-00Z.json  # Archived workflow
```

**Naming convention:** `workflow-YYYY-MM-DDTHH-MM-SSZ.json`
- ISO-8601 format with hyphens (not colons) for filesystem compatibility
- Second-precision timestamp ensures uniqueness
- Near-zero collision probability

### Auto-Resume Detection

When `/design-flow` is invoked:

```
1. Scan .claude/state/ for workflow-*.json files
2. Filter for in-progress workflows (current_phase != "complete")
3. Sort by last_updated timestamp (newest first)

If 0 workflows:
  → Start new workflow immediately

If 1 workflow found AND no product idea argument:
  → Present simple "continue" or "new" choice

If 2+ workflows found:
  → Show numbered list of all in-progress workflows
  → User selects: "continue [N]" or "new"
```

### Workflow Independence

Each workflow maintains:
- **Independent state file** - No shared data
- **Unique output directory** - `output/{project-name}/`
- **Separate iteration history** - Per-workflow tracking
- **Isolated checkpoints** - Resume at exact position

**Benefits:**
- Work on multiple product ideas simultaneously
- Switch between projects without losing context
- Compare different approaches to similar problems
- No risk of state corruption or cross-contamination

### Workflow Management

The `/workflow-status` command provides:
- View all workflows (in-progress and completed)
- Archive completed workflows to subdirectory
- Clean up old/completed workflows
- Delete specific workflows

**Storage optimization:**
- Completed workflows can be archived (moved to `archive/`)
- Old workflows can be deleted after archiving
- Generated prototypes in `output/` are never auto-deleted
- State files are small (~10-50KB each)

## Key Architectural Insights

1. **No Runtime Code** - The entire system is markdown files that Claude reads and follows. The "orchestration" happens through Claude's instruction-following capability.

2. **Separation of Concerns**:
   - Entry points handle initialization
   - Workflow guide handles control flow
   - Role prompts handle domain-specific generation
   - State files handle persistence

3. **Composable Design** - Each prompt is self-contained. You can swap, modify, or add prompts without changing the orchestrator.

4. **Human-in-the-Loop** - Every phase ends with a checkpoint requiring user approval before proceeding.

5. **Stateful Across Conversations** - JSON state files enable resuming interrupted workflows in new conversations.

6. **Iteration Tracking** - All user feedback, rejections, and revisions are captured in iteration_history arrays, providing complete audit trail and design rationale documentation.

7. **Flexible Validation** - Phase 4 (Validation) can be skipped using "approve with no validation" option to save tokens during testing/iteration cycles.
