# Architecture Overview

This project uses a **prompt-driven orchestration** pattern where Claude Code reads markdown files as instructions and follows them conversationally. There's no runtime code—the entire system is defined through structured markdown files.

---

## Component Roles

### 1. Entry Points (Commands & Skills)

**Purpose:** Initialize the workflow and hand off to the orchestrator.

| Component | Location | Trigger | Role |
|-----------|----------|---------|------|
| **Command** | `.claude/commands/design-flow.md` | `/design-flow [idea]` | Explicit invocation with argument support |
| **Skill** | `.claude/skills/design-workflow/SKILL.md` | Natural language ("I want to build...") | Auto-discovery via description matching |

Both entry points:
1. Capture the product idea
2. Load the workflow orchestrator
3. Present welcome message

### 2. Workflow Orchestrator

**Purpose:** Central control flow defining phases, transitions, and checkpoints.

| Component | Location | Role |
|-----------|----------|------|
| **Workflow Guide** | `.claude/workflows/design-centered.md` | Defines phase sequence, iteration logic, checkpoint handling |

The orchestrator:
- Specifies which **role prompts** to read for each phase
- Contains **checkpoint templates** (user approval points)
- Handles **iteration logic** (retry, revise, proceed)

### 3. Role Prompts

**Purpose:** Phase-specific instructions that Claude follows when "taking on a role."

| Phase | Prompt File | Role Assumed |
|-------|-------------|--------------|
| Discovery | `discovery-phase.md` | Product & UX Researcher |
| Exploration | `exploration-explorer.md` | Design Explorer |
| Exploration | `exploration-critique.md` | Design Critic |
| Design | `design-phase.md` | Full-Stack Developer |
| Validation | `validation-phase.md` | Product & UX Researcher |

Each prompt contains:
- Role definition and responsibilities
- Output format templates
- Quality checklists
- Iteration behavior
- Examples and guidelines

### 4. Output Artifacts

**Purpose:** Deliverables generated by the workflow.

| Artifact | Location | Generated By |
|----------|----------|--------------|
| Prototype | `output/{project-name}/` | Design phase |
| DESIGN_PROCESS.md | `output/{project-name}/` | Design phase |
| STAKEHOLDER_ALIGNMENT.md | `output/{project-name}/` | Validation phase |
| TEST_SCENARIOS.md | `output/{project-name}/` | Validation phase |

---

## Orchestration Flow

**How the workflow guide controls execution:**

```
1. Entry point loads workflow guide
2. Workflow guide says "Read .claude/prompts/discovery-phase.md"
3. Claude reads that prompt and follows its instructions
4. Claude generates artifacts per the prompt's format
5. Workflow guide defines checkpoint template
6. Claude presents checkpoint, awaits user decision
7. Based on decision, workflow guide specifies next action:
   - "approve" → proceed to next phase
   - "revise" → re-read prompt, iterate
8. Repeat for each phase
```

## Key Architectural Insights

1. **No Runtime Code** - The entire system is markdown files that Claude reads and follows. The "orchestration" happens through Claude's instruction-following capability.

2. **Separation of Concerns**:
   - Entry points handle initialization
   - Workflow guide handles control flow
   - Role prompts handle domain-specific generation
   - Output artifacts capture deliverables

3. **Composable Design** - Each prompt is self-contained. You can swap, modify, or add prompts without changing the orchestrator.

4. **Human-in-the-Loop** - Every phase ends with a checkpoint requiring user approval before proceeding.

5. **Single-Session Workflow** - Designed to be completed in one conversation, from discovery through prototype generation.

6. **Flexible Validation** - Phase 4 (Validation) can be skipped using "approve with no validation" option to save tokens during testing/iteration cycles.
